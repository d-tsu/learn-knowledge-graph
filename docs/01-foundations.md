# 基礎理論：何を表現し、何を保証できるか

## グラフからナレッジグラフへ

グラフはノードとエッジからなる。方向付きのエッジは「ユーザ → 所属ロール」のような関係を表す。経路は複数の関係の連なりであり、到達可能性は関係をたどって対象に届くかを意味する。

本資料では、ナレッジグラフを「対象を識別し、意味の定まった関係と根拠によって結び、問い合わせに利用できる知識の集合」として扱う。専用DBの製品名でも、単なる文書間リンク図でもない。

## 用語の層

| 層 | 例 | 役割 |
|---|---|---|
| 語彙 | ユーザ、ロール、権限 | 用語の意味をそろえる |
| タクソノミー | 承認画面は業務画面の一種 | 分類の階層を表す |
| オントロジー | ロールは権限を付与する | 概念と関係、その意味上の公理を定める |
| スキーマ・制約 | テストケースは根拠を一つ以上持つ | データの構造や必須条件を検証する |
| インスタンス | U-01はR-APPROVERに属する | 具体的な事実を表す |

軽量なオントロジーは用語表と関係定義から始められる。形式的推論が必要になった段階で、OWLなどへの写像を検討する。

## プロパティグラフとRDF

**プロパティグラフ**ではノードと関係に属性を持たせる。Neo4jではラベル、型付きの方向付き関係、プロパティで表現する。[Neo4j公式概説](https://neo4j.com/docs/getting-started/appendix/graphdb-concepts/)

**RDF**は主語・述語・目的語のトリプルで事実を表す。IRIで対象や関係を識別し、リテラルで値を記述する。Turtleはその記述形式の一つである。[W3C RDF Primer](https://www.w3.org/TR/rdf11-primer/)

同じ架空の事実は、例えば次のように表せる。

```text
プロパティグラフの概念表記:
(User {id: "U-01"}) -[:HAS_ROLE]-> (Role {id: "R-APPROVER"})
```

```turtle
@prefix ex: <https://example.org/kg/> .
ex:U-01 a ex:User ; ex:hasRole ex:R-APPROVER .
```

どちらでも業務知識は表現できる。相互変換では、エッジ属性、識別子、文脈の表現を設計する必要がある。形式を変えるだけで意味まで自動的に一致するわけではない。

## RDFS・OWL・SHACL・SPARQL

- **RDFS**：クラス階層やプロパティのdomain/rangeなどを記述する。domain/rangeは単純な入力拒否の制約と同じではなく、型の推論に使われる。[RDF Primer](https://www.w3.org/TR/rdf11-primer/)
- **OWL**：クラスや関係の意味、公理を記述する。対応する推論器で論理的帰結や整合性を扱う。OWLのプロファイルや推論器によって対応範囲が変わる。[OWL 2 Primer](https://www.w3.org/TR/owl2-primer/)
- **SHACL**：対象のRDFデータグラフが、指定した形・制約に適合するか検証する。例えば、根拠が最低一つあることを検査する。仕様自体の正しさを保証するものではない。[SHACL仕様](https://www.w3.org/TR/shacl/)
- **SPARQL**：RDFをパターンで問い合わせる言語。条件に合う対象や経路を検索する。[SPARQL 1.1仕様](https://www.w3.org/TR/sparql11-query/)

## 推論・検証・計画の違い

「U-01は承認者ロール」「承認者ロールは承認権限を付与する」から「U-01は承認権限を持つ」を導くには、関係の合成を定めた規則が必要である。この帰結も、ログイン済み、アカウント有効、テナント一致などを保証しない。

「テストに期待結果がない」はデータ検証の問題。「ログインしてから画面を開く」は操作の前提・効果を使った計画の問題。一般のグラフ探索やOWL推論だけで手順生成の全体を賄うことはできない。

## 未知と禁止を区別する

OWLは開世界仮定に基づく。記載がないことを直ちに偽としない。また異なる名前が必ず異なる対象を表すとも限らない。[OWL 2 Primer](https://www.w3.org/TR/owl2-primer/)

業務の権限判定では「明示的な許可以外は拒否」といった閉じた判定を採用する場合がある。これは業務規則として別に定義する。グラフに権限エッジがないだけで、未抽出なのか、禁止なのかは決められない。

| 知識の状態 | テスト作成時の扱い |
|---|---|
| 許可が確認済み | その他の前提を確認して正常系候補にする |
| 拒否が確認済み | 根拠のある異常系候補にする |
| 情報がない | 不足事項として報告する |
| 許可と拒否が競合 | 版・適用条件・優先規則を確認する |

## 復習

- RDFは表現、OWLは意味・公理、SHACLはデータ検証、SPARQLは問い合わせ。
- 推論の結果は、元の事実と規則が正しい範囲でのみ信用できる。
- 関係の経路は操作順そのものではない。

## 演習

「権限の記述がないユーザは承認できない」と言ってよい条件を説明する。答えの要点は、権限データの完全性と、拒否を決める業務規則が必要なこと。
