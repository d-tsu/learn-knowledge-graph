# 第16章：効果を評価する

更新日：2026-10-11。執筆とレビューの状況は[README](../../README.md)で確認できる。

## この章の到達点

文書検索・対応表・グラフを、同じ問いと資料で比較できるようになる。抽出・検索・回答・実行の成績を分け、品質と維持費用の両方から採用を判断する。

## 比較する目的と基準を決める

「グラフを作れた」ことは構築の結果であり、作業が改善したという評価ではない。例えば「要件変更時に、根拠付きのテスト候補を短時間で集められるか」を目的にする。

**比較基準**として、現在の作業や簡単な代替方法を用意する。全文検索と担当者の確認、IDの対応表とSQL、グラフ検索と原文の取得を、同じ対象範囲で比べる。AIを使う方式だけに新しい資料を渡すなど、条件を変えない。

| そろえるもの | 具体例 |
|---|---|
| 原本と版 | 同じ要件書・設計書・テスト仕様、同じ公開日時 |
| 問い | 同じ変更要件から見直し候補を答える |
| 利用者の範囲 | 同じアクセス権限、同じ事前知識 |
| 使える資源 | 確認時間、検索回数、AIの利用条件 |
| 採点方法 | 正解候補、根拠の位置、不明と答える条件 |

AIの検索と生成を比較する場合には、使用するモデルの版、指示、取得件数、繰返し回数も記録する。同じ条件でも生成結果が変わるなら、複数回のばらつきを示す。

## 正解例を作り、調整用と評価用を分ける

担当者が原本を読み、期待する答えと根拠を用意する。単に別のAIの回答を正解にすると、双方が同じ誤りをした場合に見逃す。

**評価用ケース**には、通常の例だけでなく、別名、同じID文字列の別対象、注記、規約の改訂、欠落、条件が両立しないテストを含める。知識が足りない問いでは「確定できない」と答えることも正解になる。

調整用ケースは抽出器や検索条件を直すために使う。評価用ケースは調整から取り分け、最後に確かめる。同じ十問へ何度も合わせた結果だけでは、新しい問いへの効果を判断しにくい。[Introduction to Information Retrieval §8.1](https://nlp.stanford.edu/IR-book/html/htmledition/information-retrieval-system-evaluation-1.html)

## 抽出・検索・生成・実行を分けて測る

一つの最終回答だけを見ると、どこを改善すべきか分からない。第7章から第15章の処理を分けて記録する。

| 段階 | 確かめること | 誤りの例 |
|---|---|---|
| 抽出・照合 | 対象・関係・条件・出典を保ったか | 職員だけの上限を全利用者へ適用した |
| 検索 | 必要な根拠と候補を取得したか | 対応があるテストを検索条件で落とした |
| 回答生成 | 根拠に沿って条件付きで説明したか | 見直し候補を修正必須と断定した |
| データ・手順 | 条件を同時に満たし、準備できるか | 合計70だけを置き、元のレコードがない |
| 実行・結果判定 | 実環境で手順を実行し、期待結果を観測したか | モデルの計算だけで実行完了と報告した |

例えば正しい根拠が検索結果にあるのに回答が誤るなら、検索の範囲を広げるだけでは解決しない。原文に条件があるのに抽出で落ちたなら、構築処理と検査を直す。

## 正確性と網羅性を数字で読む

候補を集める問いでは、**適合率**と**再現率**が使える。適合率は「返した候補のうち正しかった割合」、再現率は「見つけるべき候補のうち返せた割合」である。[Introduction to Information Retrieval §8.3](https://nlp.stanford.edu/IR-book/html/htmledition/evaluation-of-unranked-retrieval-sets-1.html)

次は計算を学ぶための架空の成績であり、本資料の実測結果ではない。見つけるべきテストが10件あり、検索結果は8件、そのうち6件が正しかったとする。

| 指標 | 計算 | この例の読み方 |
|---|---|---|
| 適合率 | 6÷8＝75% | 返した8件のうち2件は不要な候補 |
| 再現率 | 6÷10＝60% | 見つけるべき10件のうち4件を見落とした |

何を一件と数えるかを固定する。テストIDの候補を採点することと、文章全体の正しさを採点することは同じではない。該当候補がゼロの問いでは、ゼロ除算になる率を機械的に計算せず、空の結果を正しく返せたかを別に記録する。

根拠の評価には、参照先が開けるか、引用箇所が結論を支えるか、適用条件・版が合うかを使う。誤った出典を多数付けても、根拠付きの回答として高く評価しない。

## 構築と維持の費用を含める

検索にかかった時間だけでなく、語彙とモデルの設計、原本の整理、抽出候補の確認、変更時の更新に必要な時間を測る。AIやDBの利用費、実行時間、担当者の学習も費用に含める。

例えば一回の検索が短くなっても、月一回の規約改訂のたびに大量の誤抽出を修正するなら、総作業は増える可能性がある。第8章の撤回・削除・索引更新まで含む変更例を評価へ入れる。

| 場面 | 記録する費用・品質 |
|---|---|
| 初期構築 | モデル設計、取り込み、確認した件数と工数 |
| 日常利用 | 回答時間、根拠確認時間、利用費、誤回答の種類 |
| 原本改訂 | 再構築、指摘対応、古い回答が残った期間 |
| 障害・移行 | 復旧時間、必要な原本・版・設定を取り出せたか |

小さな試行の結果を、そのまま大規模運用の成績へ広げない。対象とした資料量、問い合わせの種類、利用人数を併記する。

## 採用・縮小・見送りを決める

試行前に合格条件を決める。例えば「重大な条件の欠落はゼロ」「見直し候補の再現率を現在の方法以上にする」「担当者の確認を含む総工数を減らす」とする。必要な水準は、その用途で見落としが与える影響によって決める。

条件を満たさなければ、対象を絞る、抽出だけを手作業に戻す、対応表と検索を継続する、といった選択がある。採用するときも、どの問いに効果があったかを示す。「グラフ全般が優れている」という結論へ広げない。

## 復習

- 抽出の評価と検索の評価を分ける理由は何か。
- 適合率が高くても、候補の見落としが多い場合があるのはなぜか。
- 日常の回答時間以外に、どの費用を測るか。

## 演習と解答例

### 演習1：候補が減った

方式Aは見つけるべき10件のうち8件を返し、不要な候補を2件返した。方式Bは正しい5件だけを返した。両方式の適合率と再現率を求め、どちらが常に優れていると言えるか考えよう。

解答例：Aは適合率8÷10＝80%、再現率8÷10＝80%。Bは適合率5÷5＝100%、再現率5÷10＝50%である。Bは不要な候補が少ないが、見落としが多い。見直し漏れの影響と確認工数を合わせて判断するため、一つの率だけで優劣を決められない。

### 演習2：更新後に古い答えが出る

通常の検索では高得点だったが、規約改訂後も旧版の上限を答えた。どの工程と評価ケースを見直すか。

解答例：原本の適用期間、主張の失効、導出と索引の再構築、検索の版指定、回答キャッシュを確認する。改訂前後の日時を指定するケースと、撤回した根拠が現行回答に残らないケースを追加する。通常時の成績だけでは更新の品質を評価できない。
