# 既存章に追加する図の提案

検討日：2026-10-11。対象は今回の執筆前に存在した序章〜第5章。初学者のエンジニアを想定した[独立した検討](../reviews/2026-10-11-existing-diagram-proposals.md)を基に、読み取りの負担と文章・表との重複を比べた。

## 優先する候補

| 優先度・箇所 | 図にする内容 | 提案する理由 | 量を増やしすぎない方法 |
|---|---|---|---|
| 高：第3章「関係の種類と向きを選んでたどる」 | 記録は貸出→利用者、検索は利用者→貸出→蔵書 | 記録した矢印と探索する向きを頭の中で重ねずに読める。逆関係の推論との混同も減らせる | 一経路だけを取り出して手順を示し、既存の番号付き説明を置き換える |
| 高：第3章「対象の同一性」 | 三つの台帳の記録を、二冊の本へ対応付ける | 記録の数と、現実の対象の数の違いが見える。同じID文字列だけで統合しない理由が具体的になる | 表を残すなら「統合後は二冊」と一文で示す方法もある。図と詳しい文章を重ねない |
| 中：第5章「借りた人がいる／記載されている」 | 一つの未記載データから、存在公理と記載検査へ分岐する | 同じ入力でも、調べる内容が違うため結果が違うことを見比べられる | 現在の比較表との置換を検討する。説明の多い箱になるなら表を維持する |
| 中：第5章「値の日時」 | 10時の状態、10時30分の変化、11時の取得と判断 | 新しく取得したファイルでも、中身の状態は古い場合があると分かる | 時系列表を置き換え、計算例を図へ移す。利用者区分や規則の版まで詰め込まない |

四件すべてを追加する必要はない。図を読むための説明が増える箇所は、短い文章や表の方がよい。色だけで区別せず、矢印が関係・探索手順・時間・入力と結果のどれを表すかを明記する。

## 図を増やさない箇所

第1章のデータ・情報・知識と入力形式・業務規則は、同じ比較軸の表を維持する。固定した階段や直列フローにすると、知識の区分や確認の順番を必要以上に固定して見せるおそれがある。

第2章の概念モデル・オントロジーは、既存の図と定義表を使う。二つを別工程の箱へ分ける図は、意味の有無で分けるような誤解を招く。第4章のクラス・個体・構成なども既存図で主要な区別を示しているため、追加を優先しない。

## 採否と確認状態

全章通読後、次のように反映した。理解への効果は、実読者による確認が必要になる。

| 候補 | 採否と理由 |
|---|---|
| 第3章の探索順 | 採用。番号付き手順を一経路の図に置き換え、関係の向きと探索順を見比べられるようにした |
| 第3章の同一性 | 図は追加せず、表の説明を「統合後の蔵書ノードは二つ」と明示する文へ置き換えた。表との重複を避けながら結果を示せる |
| 第5章の存在と記載 | 今回は表を維持。二つの問いと結果を同じ列で比較でき、文章の多い箱へ置き換える利点は小さい |
| 第5章の二つの日時 | 今回は時系列表を維持。図案は将来の候補として残すが、現状の三時点と計算を表から読めるため追加を優先しない |

新たに執筆した章では、通読レビューを受けて第6章の既存図を条件付きの規則の図へ、第8章の既存図を改訂前後の図へ置き換えた。図の点数を増やさず、各章で新しく学ぶ内容に合わせた。[全体レビューと確認範囲](../reviews/2026-10-11-book-review.md)に修正と再確認を記録する。
