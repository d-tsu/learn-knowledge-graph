## 改稿内容

| 読者からの指摘 | 改稿での対応 |
|---|---|
| 主語や説明の対象をたどりづらい。読点が多い | 開発者・受付担当者などの行為者と、扱う対象を明記。複数の話題をつないでいた文章を分けた |
| 「記録」「意味をそろえる」「定義と記録を合わせる」が不明 | 序章でR-01/T-01の内容を表にし、用語・関係の定義と個別の対応付けを順に説明 |
| 不自然な書き出し | 用語の紹介、学習の順序、各整理方法の用途を直接説明する書き出しに変更 |
| 文書を検索した後に何をするのか不明 | 名前が一致・不一致になる小例を表にし、開発者が項目の対応と条件を確認する作業を説明 |
| PG/RDFに図がほしい。日本語の強調が崩れる | 同じ所属・年齢の例で図2点を追加。強調範囲を用語に限定し、括弧の正式名称を外に出した |
| データ・情報・知識の違いが分からない | 「2」→U-03の現在の貸出冊数→上限3冊を使った判断という一つの例を表で比較 |
| 「発行範囲」「判断する時点」が不明 | 図書室ごとのIDの割り当てと、貸出確定直前の確認を具体的に説明。値の日時と確認のタイミングを区別 |
| 貸出IDが本や人のIDに見える | A-017/U-03/L-08の識別対象を先に説明し、「この貸出で貸した本」「この貸出で本を借りた人」に変更 |
| 入力できることと業務規則の区別が不明 | 入力形式の確認と業務規則の確認を表で比較。タイミングの違いは別の節で扱う |
| 拒否条件の二重否定が読みにくい | 「上限以内」と直接表現し、ほかに確認する規則の具体例を添えた |

## セルフレビュー

3章を序章から順に読み、用語の初出、段落の主題、具体例の対象、演習の根拠を確認した。第2章も整理方法ごとの用途を明記し、検索用概念とクラスの説明順を整理した。

| 観点 | 確認結果と範囲 |
|---|---|
| 初出の用語・前提・説明の十分さ | 具体例の後に抽象的な区分を説明。貸出の出来事とID、入力形式と業務規則、値の日時と操作のタイミングを確認 |
| 正確性・根拠 | PG/RDF、OWLのクラス分類、SKOSの概念関係を公式資料で照合。図書室の区分・規則は教材独自の例と明記 |
| 図・表・演習 | IDと対象、上限3冊、入力2冊の計算を照合。未提示の応用仕様を確定しない。図5点の描画と目視を実施 |
| 構成・章間の整合 | OUTLINEの章の役割を維持。一般基礎は図書室、開発の応用は序章の動機と後続章で扱う |
| 読みやすさ | 主語、指示語、抽象語の参照先を確認。二重否定と説明を飛ばす表現を修正 |
| 技術的な体裁 | 内部リンク12件、コードフェンス、強調24箇所を機械的に確認。描画と強調の表示も目視確認 |

確認に使用した一次資料：

- [Neo4j Graph database concepts](https://neo4j.com/docs/getting-started/appendix/graphdb-concepts/)：点・線と属性。

- [W3C OWL 2 Primer](https://www.w3.org/TR/owl2-primer/)：クラス・個体・公理と分類の推論。
- [W3C SKOS Primer §2・§2.3・§5.2](https://www.w3.org/TR/skos-primer/)：名称・概念関係、全体と部分、OWLクラスとの区別。
